# 机场地面保障作业管理平台

面向航班保障、机位分配、廊桥靠接、摆渡车调度、行李装卸、航油加注、除冰作业与延误处置的一体化机场地面保障作业工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `airport-ground-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 地面电源（电源车）职责与归属

电源车的规则比普通模块严，全部在 `frontend/src/api/gpu-service.ts` 裁决，页面不传判断：

- **身份**：接机供电、结束供电、申请检修、电缆检查都只能由当班「值班员」操作；其他角色
  （观察员）只能查看供电记录，不能改动。身份、班组、班次在电源车页面顶部切换。
- **归属**：发起供电时记录归属班组与值班员；跨班组结束别人发起的供电一律拒绝。点「交接班」
  后归属随班次移交给新班组，并在供电记录里留一条变更记录。
- **功率核对**：发起前按航班号查航班保障模块的机型，对照 `src/data/gpu-rules.ts` 的
  机型功率需求表；设备功率等级不够的一律拒绝，并说明需求、能力与差值（kVA）。
- **电缆检查**：电缆检查未通过的设备进不了供电中；待命设备可先登记「电缆检查」。
- **排队**：同一台设备同一时段只保障一个航班。设备忙时新请求登记排队，按申请时间先到先得
  （同刻按航班号升序）；设备空出后队首航班有优先权，插队会被拒绝。
- **状态链**：设备状态只能按 待命→供电中→待命→待检修 变动，跳级（如供电中直接转待检修）
  一律拦下。
- **资源缺口同源**：每次供电发起、结束或转检修后，按电源车现状重算资源计划的「资源缺口」；
  保障资源调度页的「电源车可调度台数」与电源车数据同源，不另存数字。

供电记录与排队队列存在本地数据层的 `gpuLog`、`gpuQueue` 两个 key 下，随其它数据一起持久化。
